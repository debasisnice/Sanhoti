## 2. Action Plan

### P0 — Technical fixes (week 1) — highest impact

1. **Kill the `/index.html` duplicate.**
   - 301 redirect `/index.html` → `/` at Nginx (and any other stale static paths Google indexed).
   - Add `<link rel="canonical" href="https://www.sanhoti.org/">` to the *static* `frontend/index.html` head so it exists before JS runs. (Per-page Helmet canonical overrides it after hydration.)
   - Also 301 non-www → www (verify this is already in place).
   - In Google Search Console: URL-inspect `/index.html`, request removal/recrawl.

2. **Serve the dynamic sitemap.** `SitemapController` already exists — wire Nginx so `https://www.sanhoti.org/sitemap.xml` proxies to the backend route instead of serving the static file. Add per-event URLs (`/events/:id`) and gallery URLs with real `lastmod`. Resubmit in Search Console.

3. **Pre-render for crawlers (the single biggest gap).** Options, cheapest first:
   - **Extend the existing crawler-sniffing pattern.** `EventController.isLinkPreviewCrawler` already detects bots for `/og/` routes. Generalize: for Googlebot/Bingbot requests to `/`, `/about`, `/events`, `/events/:id`, serve server-generated HTML (title, meta, canonical, JSON-LD, and the actual text content from the JSON data files). This is dynamic rendering — Google supports it.
   - Or **build-time prerender** (e.g. `vite-plugin-prerender` / `vite-ssg`) for the static pages (`/`, `/about`, `/contact`, `/donate`), keeping dynamic rendering for event pages.
   - Full SSR migration is not needed; either of the above closes the gap.

4. **Static homepage content fallback.** Even without full prerendering, put one crawlable `<h1>` + a paragraph of real text (see P1 copy below) inside `<div id="root">` in `index.html` (React replaces it on mount). Crawlers that don't execute JS see real content instead of an empty div.

### P1 — Content: win the "Durga Puja" queries (weeks 1–3)

Aikotaan ranks with a *dedicated page per festival*. Sanhoti has none. Nobody ranks for "Durga Puja Costa Mesa 2026" yet — first mover wins.

5. **Create a permanent landing page: `/durga-puja`** (evergreen URL, updated each year — do NOT put the year in the URL; put it in the title).
   - Title: `Durga Puja in Orange County 2026 | Sanhoti — Costa Mesa, CA`
   - H1: `Durga Puja in Orange County 2026`
   - Content must naturally include: **Costa Mesa**, **Estancia High School** (or 2026 venue), **near Irvine**, **Southern California**, dates (Oct 16–21, 2026), schedule (Shashthi → Vijayadashami), pushpanjali, dhunuchi naach, cultural evenings/concerts, Bengali food, how to attend/RSVP, parking, photos from Durgotsav 2025.
   - Add `Event` JSON-LD (reuse `src/seo/eventJsonLd.ts`) with `location` (venue + Costa Mesa address + geo), `startDate`/`endDate`, `offers` (free/ticketed), `performer` for concerts. This makes Sanhoti eligible for Google's event rich results and Google "Events near me" — Aikotaan has no structured data.
   - FAQ section ("Where is Durga Puja celebrated in Orange County?", "Is there Durga Puja near Irvine?") with `FAQPage` JSON-LD.
   - Internal links: homepage hero → `/durga-puja`; `/events` → `/durga-puja`.

6. **Repeat for other target queries:**
   - `/bengali-events-orange-county` or a `/festivals` hub — targets "Bengali festival Orange County", links to Durga Puja, Saraswati Puja, Poila Boishakh pages.
   - Concert/cultural-night section on the Durga Puja page (or its own page) targeting "Bengali concert Southern California" — name the artists (artist names are high-volume queries themselves).

7. **Homepage title/meta refresh.** Work "Durga Puja" into the homepage:
   - Title: `Sanhoti — Bengali Association of Orange County, CA | Durga Puja & Cultural Events`
   - First H1/paragraph mentions Durga Puja in Costa Mesa and events near Irvine.

8. **Per-event pages with real slugs.** `/events/:id` with a 12-char alphanumeric ID is meaningless to Google. Move to `/events/durga-puja-2026-<id>` (slug + ID, pattern already used for upload folders). 301 old URLs.

9. **Past-event recap posts** (galleries + short write-ups): "Durgotsav 2025 at Estancia High School, Costa Mesa — Highlights". Fresh, keyword-rich, image-heavy content that accumulates long-tail rankings. Aikotaan's event archive is exactly this and it ranks.

### P2 — Local & off-page SEO (weeks 2–6) — this is where rankings are actually decided

10. **Google Business Profile** (nonprofit category "Non-profit organization" / "Cultural association"). Aikotaan has a Maps listing; a GBP is required to appear in the local pack for "near me"/"near Irvine" queries. Post events to it.

11. **NAP consistency.** Put name, Rancho Santa Margarita address, phone, EIN in the site footer (crawlable text, matching the JSON-LD exactly).

12. **Event listings & citations** — each is a backlink plus a ranking surface of its own:
    - AllEvents.in (Aikotaan's events rank on Google via AllEvents), Eventbrite, Meetup
    - drikpanchang local listings, Indian Eagle / TravelBeats (they list SoCal Durga Pujas — email them)
    - Yelp, local OC event calendars (OC Register, Visit Costa Mesa, city calendars), Patch.com
    - utsavpedia/Bengali diaspora directories; cross-links from BASC-adjacent orgs where friendly

13. **Social profiles** on Instagram/X/Facebook page (not just group) linking back with consistent name; add all to JSON-LD `sameAs`.

14. **School/venue links.** Ask Estancia High School / venue and sponsors to link to sanhoti.org. Sponsor pages linking back = easy relevant backlinks.

### P3 — Measurement & maintenance

15. **Google Search Console + Bing Webmaster Tools**: verify, submit sitemap, monitor which queries show impressions; fix coverage errors (expect duplicate/`index.html` issues initially).
16. Track target keywords monthly (manual or a rank tracker). Watch for the Durga Puja page entering the top 10 within 4–8 weeks of publishing.
17. **Every year in June/July**: update `/durga-puja` with new year, dates, venue, ticket link — before Aikotaan publishes theirs (their 2025 page went up close to the event; publishing early wins the "2026" query).

## 3. Why this wins

- Aikotaan's advantage is 100% structural (WordPress renders HTML, has per-event pages, has citations). Nothing they do is sophisticated — no structured data, no meta descriptions, generic title.
- Sanhoti already has better metadata and JSON-LD infrastructure; it just needs to be **visible to crawlers** (P0), **aimed at the actual queries** (P1 — nobody has a dedicated "Durga Puja Orange County 2026" page yet), and **corroborated off-site** (P2).
- Event rich results + GBP local pack are two SERP features Aikotaan doesn't occupy at all — Sanhoti can appear above their #1 blue link.
